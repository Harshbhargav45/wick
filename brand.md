## Typography — Instrument Serif + Inter + JetBrains Mono

- **Display (hero/headlines only):** Instrument Serif
- **Body / UI:** Inter
- **Mono (numbers, addresses, code):** JetBrains Mono

Wired via `next/font/google` in `frontend/src/app/layout.tsx`. CSS variables: `--font-serif`, `--font-sans`, `--font-mono`.

### Type scale (recommended)

| Role | Class | Use |
|---|---|---|
| Display | `font-serif text-5xl font-semibold tracking-tight` | Hero only, one per page |
| H1 (page) | `text-3xl font-semibold tracking-tight` | Page title |
| H2 (section) | `text-xl font-semibold` | Section breaks |
| H3 (subsection) | `text-base font-medium` | Card titles |
| Body | `text-sm` | Default UI text |
| Reading | `text-base leading-7` | Long-form content |
| Small / caption | `text-xs text-muted-foreground` | Meta, timestamps |
| Mono | `font-mono tabular-nums` | Numbers, addresses, code |

Use the serif only for hero/display moments. Everything interactive and data-dense stays sans + mono — the serif is the editorial voice, not the workhorse.

## Gradients

Two gradients derived from the palette, exposed as Tailwind utilities `bg-brand-bg` and `bg-brand-accent`.

### Background gradient (subtle)

```css
--gradient-bg: linear-gradient(135deg, oklch(0.13 0.015 60) 0%, oklch(0.16 0.02 75) 100%);
```

**Use for:** hero sections, page headers, large empty areas.
**Do not use for:** body text backgrounds, form fields, cards.

### Accent gradient (ember → copper)

```css
--gradient-accent: linear-gradient(to right, oklch(0.75 0.15 70) 0%, oklch(0.78 0.16 95) 100%);
```

**Use for:** primary hero CTAs only (never as a text background).
**Do not use for:** body text, form submit buttons — keep those solid `bg-primary`.
One gradient per screen, max. Do not animate gradients on hover.

## Tone and voice

### Words to use

Direct, specific, number-forward. Say what the guard actually did — reduce sizes, latencies in µs, thresholds in ratios. Describe outcomes, not feelings ("reduced 18%" not "protected you from disaster"). Second person ("your position") is fine; verbs beat adjectives.

### Words to avoid

Hype words — revolutionary, game-changing, unleash, supercharge, seamless, powerful. "Unlock" is banned. Emojis and exclamation marks. Anything that manufactures urgency ("act now", "limited time") — the guard's entire point is that you don't have to act.

### Voice example

> Your SOL-PERP is underwater — health 0.98, below the 1.00 trigger. Wick already reduced 18% of the position, signed as your Drift delegate, 375µs after the tick.

## Usage dos and don'ts

**Do:**

- Use the shadcn CSS variables (`bg-background`, `text-foreground`, `bg-primary`, `border-border`) everywhere. Never hardcode hex.
- Use `font-mono tabular-nums` for any number that updates in place (health factor, latency, prices).
- Keep the 4 px spacing grid (`gap-2`, `p-4`, `px-6`).
- Test every component in both light and dark mode before considering it done.
- Default the app to dark (Wick is a watch console) but keep the light toggle working.

**Don't:**

- Hardcode colors in component files.
- Use `transition: all` — always specify `transition-colors`, `transition-transform`, etc.
- Mix more than one gradient on the same screen.
- Use the accent gradient as a background for body text.
- Override tokens per-component — if a color is wrong, fix it in `globals.css` once.
- Use the ember accent for danger/warn semantics — those stay amber-out and red (`--warning` / `--danger`).
