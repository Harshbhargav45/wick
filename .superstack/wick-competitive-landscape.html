Onchain liquidation-protection layer for existing Solana perps (FlashTrade, Jupiter Perps) · compiled 2026-08-07
Crowdedness (direct niche): moderate

Threats are real but none occupy the exact wedge. The direct wedge — trustless, sub-50ms, onchain auto-execution that beats the liquidator — is unclaimed. Adjacent categories (alerts, liquidation bots, CEX bots, venue-native TP/SL) are crowded; the winning side of the race is what no one sells.

3. Dead / failed (landmines)

  • "Auto-add-collateral" scripts/guides — never shipped trustless; ones that existed ran a single trusted bot key = replicated custody. Lesson: users demand a presented, honest authority model.
  • "Position manager" tools — most shipped alerts, none shipped the trigger. Lesson: the gap is execution, not notification.

4. Moat

  • Type: technical complexity + venue-adapter lock-in (deliberately thin); network effects seeded later.
  • Differentiation: only anti-liquidation layer that is trustless, sub-50ms, co-signed margin wallet, honest latency labels.
  • Biggest threat: venue absorbing advanced-order features (LimitBook absorption pattern).

5. Verdict

The direct, valuable wedge — executing protection before the liquidator, with verifiable custody — is moderate: real adjacent traction, but no winner in the exact lane. Opportunity: lead with the two honest speed tiers and the latency/verifiability proof, since no alert-only or keeper-based substitute can match an in-session sub-50ms action.
